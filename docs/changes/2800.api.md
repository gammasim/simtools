``--simulation_software`` takes a list of chain stages (for example ``corsika sim_telarray`` or ``corsika obdeect_atmosphere obdeect_optics sim_telarray:bypass_optics=camera_only``) instead of one choice such as ``corsika_sim_telarray``. Simulation programs, chain stages, stage options, data products and program files are declared in ``resources/simulation_software.yml``, read with ``simtools.runtime.software_catalog``; the program files moved there from ``resources/file_types.yml``. Ray-tracing backends are the software entries with a ``ray_tracing_backend`` field in that catalog, and ``--ray_tracing_backend`` (or ``SIMTOOLS_RAY_TRACING_BACKEND``) selects one of them (default ``sim_telarray``). The shower-route modules (``runners.shower_routing``, ``simtel.shower_route``, ``simtel.shower_photons``) and their options ``--shower_route_mode`` and ``--shower_route_threads`` are removed. The option ``bypass_optics`` of ``sim_telarray`` takes the strings ``none`` (default), ``camera_entrance`` and ``camera_only``; integers are no longer accepted. ``register_stage`` takes a stage class, and ``dependencies.validate_simulation_dependencies`` takes the software of the chain stages. Removed ``constants.SIMULATION_SOFTWARE_DEPENDENCIES``, ``constants.SIMULATION_SOFTWARE_DEFAULT``, ``constants.LIGHT_EMISSION_CHAIN_DEFAULT`` and ``simulation_software.products``. Production definition schema 1.1.0 lists the chain stages.
